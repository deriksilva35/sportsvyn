The Daily — homepage module, mock v1

READ THIS FIRST — two things I found that change what you're judging.

1. Production is not paper. The brief and design-tokens-v1.1 both say the Daily Card homepage is a PAPER surface. The live page is not: .daily-card is background: var(--graphite) (home.css:406) and sportsvyn.com/ serves five data-surface="ink" and zero paper. So the paper mock below is the Surface Rule TARGET, not what this module would drop into today. I've mocked the ink ground too, at the bottom, so the hierarchy call is judgeable against what's actually live. If paper is imminent, judge the top. If not, judge the bottom.

2. Name collision. The page is titled "The Daily Card". The game is "The Daily". A module reading THE DAILY inside a page reading The Daily Card is two different things wearing one word. Worth resolving before build — the mock uses "THE DAILY" in the eyebrow so you can see the clash rather than have me paper over it.

Rules followed: no volt text on paper anywhere. Volt appears only as the 14px eyebrow square, the 4px module left bar, ink-on-volt chips (PLAY, tier), the 2px link underline, and the score bar fill. Wordmark is ink-band only. Saira 900 italic for hooks, JetBrains Mono for every number, Source Serif italic for prose.

Position — my proposal, argued: directly under the byline, ABOVE Draftvyn. Your instinct is right and here is the reason to hold it: the Daily is the only module on the page that EXPIRES. Draftvyn is a standing invitation ("three free drafts a week"); Today's Reads is durable; the season strip is a calendar. A page that renames itself daily should lead with the thing that is only true today. It also has the only state that CHANGES for a returning reader — the receipt — which makes the top slot do work on the second visit instead of repeating an ad.

Edition number: shown as 001. Derived from days since the first PROD board (2026-08-16), not stored, so it needs no column.
